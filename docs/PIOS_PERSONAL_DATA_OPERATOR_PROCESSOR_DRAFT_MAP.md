# PIOS — Карта «оператор / обработчик» по потокам данных (черновик, не юридическое заключение)

**Статус: черновик для передачи юристу, не решение и не ADR.** Составлен по прямому запросу продукт-овнера (2026-09-07) — проанализировать PIOS как B2B SaaS / Business Network Platform и определить для каждого потока данных, кто оператор, кто обработчик по поручению, и где PIOS становится самостоятельным оператором, в терминах 152-ФЗ «О персональных данных».

**Обязательная оговорка.** Это структурная раскладка по фактам архитектуры (кто какие данные видит, кто решает цель обработки), а не юридическая классификация. Термины «оператор» и «обработчик по поручению» — формальные категории 152-ФЗ с конкретными правовыми последствиями. Итоговую классификацию по каждой строке должен подтвердить юрист, специализирующийся на персональных данных, до того как эта карта повлияет на реализацию чего-либо.

## Карта потоков

| Поток | Данные | Кто определяет цель/состав | Черновая роль PIOS | Обоснование |
|---|---|---|---|---|
| **Identity** — регистрация, вход | телефон (логин), пароль (хеш), сессия | PIOS | Оператор | Прямые отношения платформы с человеком; PIOS сам решает, зачем нужен аккаунт — не «по поручению» водителя |
| **Driver Management** — профиль водителя, машина | имя, номер/модель машины, вместимость | PIOS | Оператор | Операционная запись самой платформы для диспетчеризации |
| **Order Management / Dispatch** — заказ, поездка, цена | детали поездки, кто с кем едет, цена | двойственно | Оператор для факта записи; коммерческая сторона — вне PIOS | Фиксация поездки — функция платформы; цену/деньги платформа принципиально не определяет и не проводит (`ADR-042`, `PRODUCT_DECISION_MVP_PILOT_BOUNDARY.md`) |
| **Passenger Experience** — «Круг доверия» (`Connection`, `isPrimary`) | связь пассажир↔водитель | пограничный случай | **Требует отдельного решения** — см. ниже | Это данные о клиентской базе конкретного водителя-предпринимателя, а не платформы (`PRODUCT_DECISION_ENTREPRENEUR_MODEL.md` Section 2.6 «Reference, not ownership») |
| **AI-советник владельца** (`ai-advisor`, уже работает) | агрегированные цифры, без личных данных | — | 152-ФЗ не применяется | По конструкции (`ADR-056`) в запрос вообще не попадает ничего похожего на персональные данные — спроектированное ограничение, не случайность |
| **AI служба поддержки** (обсуждается, не построена) | весь текст пользователя, потенциально телефон/имя/детали заказа | PIOS определяет цель и состав, AI-провайдер исполняет по этому заданию | PIOS = оператор; провайдер = вероятно обработчик по поручению, но зависит от условий конкретного провайдера | Требует проверки: не использует ли провайдер данные ещё и для своих целей (это меняет схему на более сложную) — см. `docs/PIOS_SUPPORT_AND_CONTACT_CHANNEL_ROADMAP.md`, уже открытый вопрос |
| **Хостинг (Beget)** | вся база данных PIOS физически | PIOS | Обработчик, по договору хостинга | Стандартная инфраструктурная схема |
| **Network Management** (будущая «сеть предпринимателей», B2B-видение) | не подключён ни к одному реальному экрану | — | Не актуально сегодня | Существует в коде, но нигде не используется в продакшене (`PIOS_TAXI_V1_TARGET_ARCHITECTURE.md` разд. 14) |

## Ключевой вопрос для юриста — двухслойная модель

Продуктовая философия PIOS (`PIOS_PRODUCT_VISION.md`, `PRODUCT_DECISION_ENTREPRENEUR_MODEL.md`) заявляет: клиент принадлежит предпринимателю (водителю), а не платформе — это архитектурно закреплено, не только маркетингово (данные о связи водитель↔клиент не собираются платформой в единый граф; связи между модулями — идентификаторы, не копии данных).

Отсюда реальный вопрос: может ли PIOS для данных именно о клиентской базе конкретного водителя (строка «Круг доверия» выше, и частично «Order/Dispatch») выступать **обработчиком по поручению** самого водителя — то есть водитель как самостоятельный предприниматель является оператором данных своих клиентов, а PIOS обрабатывает их по его поручению как инфраструктура (стандартная схема для B2B SaaS/CRM-платформ)? Для Identity такая логика не подходит — там отношения «человек↔платформа» прямые, PIOS точно оператор.

Если эта двухслойная модель юридически состоятельна — её стоит закрепить в пользовательском соглашении с водителями. **Это не подтверждено и не может быть подтверждено этим документом** — нужна проверка юриста, что конструкция реально работает по 152-ФЗ, а не просто логично звучит.
